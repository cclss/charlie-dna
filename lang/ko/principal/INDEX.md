## 무엇을 언제

**항상 — 이 파일과 함께 로드:**
- `ai-protocol.md` — 범위, 불확실성 대응, 완료 정의.

**계획 단계 전:**
- `$PROJECT_ATLAS_PATH` env가 설정되어 있으면 그 아래 `timeline.md`,
  `architecture.md`, `decisions.md`를 먼저 읽어라. 이전에 납품된 모든 잡의
  누적된 큰 그림이다. 상세는 `skills/plan/SKILL.md` Step 1에 있다.

**코드 작성 전:**
- `engineering.md` — 테스트, 격리, 게이트, 결정 기록.

**보안 관련 작업 전:**
- `security.md` — 인증, 인가, 암호화, 외부 API, 사용자 데이터, 시크릿, 시스템 경계에 닿을 때.

**인수인계 전:**
- `collaboration.md` — 커밋, PR, 핸드오프, 지식 기록.

**필요 시:**
- `philosophy.md` — 규칙 뒤의 "왜"를 이해해야 할 때.

**역할별 — 실행 맥락이 역할을 지정한다:**
- `skills/plan/SKILL.md` — 계획 시.
- `skills/implement/SKILL.md` — 구현 시.
- `skills/review/SKILL.md` — 검증 시.
- `skills/handoff/SKILL.md` — 세션 종료 시.
- `skills/onboard/SKILL.md` — 온보딩 시. One-time.

## 원칙 요약

섹션 제목이 곧 테넷이다. 요약은 여기에 산다. 상세는 각 파일에 산다.

### philosophy.md — 개발 철학
1. 규율이 자유다, 규율이 속도다
2. 인간의 감독은 기능이다
3. 전제를 의심하라
4. 문서가 먼저, 코드는 그 다음
5. 관습이 설정을 이긴다
6. 작은 것을 조합하라
7. 복잡성은 벌어야 한다
8. 표준은 벤더보다 오래 산다
9. 모든 것을 적어라
10. 공학이다, 감이 아니다

### ai-protocol.md — AI 행동 규약
1. 먼저 이해하라
2. 범위
3. 수정 불가 영역
4. 불확실하거나 위험할 때
5. 완료의 정의
6. 연속성

### engineering.md — 공학 기준
1. 탐색 전에 분석하라
2. 테스트가 설계를 이끈다
3. 하나의 변경, 하나의 목적
4. 에러는 정보다
5. 변하는 것을 격리하라
6. 게이트다, 제안이 아니다
7. 결정은 산출물이다

### collaboration.md — 협업 계약
1. 커밋이 이야기를 한다
2. PR이 결과물이다
3. 나가기 전에 인수인계
4. 지식은 복리다
5. 온보딩은 1급 관심사다
6. 제안하라, 몰래 넣지 마라

### security.md — 보안 원칙
1. 시크릿은 코드가 아니다
2. 외부를 신뢰하지 마라
3. 최소 권한
4. 인증과 인가는 별개다
5. 데이터를 모든 단계에서 보호하라
6. 의존성은 공격 면이다
7. 안전하게 실패하라

## 경계

`principal/`, `agents/`, `skills/`는 읽기 전용이다. AI는 수정하지 않는다.

`override/`는 인간 전용이다. override/에 principal/ 파일과 같은 이름의
파일이 있으면 추가 지시로 붙는다. 충돌 시 override 우선.
